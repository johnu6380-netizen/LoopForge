# Data provenance

Everything the site shows comes from `web/public/data/` and `web/public/evidence/`.
Both folders are generated by `loopforge exp export` and are never edited by hand.

## Where the numbers come from

- Two finalized experiments: `gpt-01` and `claude-01`. Each is ONE hill-climb run of 6 chained turns.
  Every turn was a new chat with memory and code execution off, so they are 6 sessions, not 6 independent samples.
- Seed program: `nearest_neighbor`. Hints: off. Per-instance time limit: 10 s.
- Dev set (seed base 1000) is what the models were shown. The test set (seed base 2,000,000)
  was scored once, at `finalize`.
- Fitness = mean over 12 instances of tour length divided by the 2-opt reference tour length. Lower is better.
  1.0 ties 2-opt. Any invalid instance makes the candidate invalid.

## What is not recorded

- **Descriptions.** The `DESCRIPTION:` lines could not be parsed, so they were removed from the saved
  replies. Every candidate's description reads "LLM edit" in the archive. The site shows "not recorded".
- Model names ("GPT-6", "Sonnet 5.5") are the labels typed by the owner when creating each experiment.

## How it is checked

`node web/scripts/validate-data.mjs` re-derives tour validity, length, ratio and fitness from the stored
points and tours, compares the headline numbers with the `finalize` output, verifies the sha256 of every
saved prompt, reply and program, and scans for emails and personal paths. It never runs candidate code.

## Excluded

`experiments/dry-run` is a throwaway test. It is not finalized, so the exporter skips it.
